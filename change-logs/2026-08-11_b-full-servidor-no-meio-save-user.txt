===============================================================================
O QUE MUDOU
===============================================================================
supabase/functions/save-user/index.ts (Deno / Edge Function):
- Recebe { email, payload }; usa o service_role; faz read (payload,rev) → merge (mergeUser, mesma
  regra do cliente no ramo sem-ancestral: newest-wins por userUpdatedAt; role pelo roleUpdatedAt) →
  UPDATE ... where email e rev=esperado (CAS atômico) → 0 linhas = conflito → re-tenta. Usuário novo
  = insert (rev 0). Exige Authorization (não fica aberta).
supabase/functions/save-user/DEPLOY.md: passo-a-passo de ativação (supabase functions deploy save-user
  + _USE_SAVE_API=true).

index.html:
- Flag _USE_SAVE_API (false por padrão) + saveUserViaApi (chama sb.functions.invoke('save-user'),
  usa o payload MESCLADO que o servidor devolve pra atualizar baseline/local; marca _saveApiOk=false
  e cai no fallback se a função não responder).
- sbPushUsers roteia: SERVIDOR (Edge Function) → se indisponível, RPC save_user (B-lite, já ativo) →
  se não, caminho antigo. Com o flag false, nada muda (o RPC continua fazendo o trabalho).
