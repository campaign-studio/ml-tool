DIAGNÓSTICO (confirmado, só leitura, direto no banco)
===============================================================================
O tokenizer (versão que gerou esses HTMLs) injetou {%translation%} DENTRO de <...>, em 3 formas:
1) MATCH DE SUBSTRING LIXO: `cross{%translation id22%}or{%endtranslation%}igin`. id22 é a
   "tradução" da palavra "or" (2 letras), que casou dentro do keyword `crossorigin`. Em romeno
   "or" = "sau" -> vira `crosssauigin`/`sauder` (o Trecho 2). Uma linha de CSV inteiramente espúria.
2) DENTRO DE alt="...": `alt="{%translation id27%}Not a gym person?{%endtranslation%}"`. Em RO =
   "Nu faci sport?" (o Trecho 1). Idem id30/id33.
3) DENTRO DE src="...png": `<img src="{%translation id2%}https://...png{%endtranslation%}">`. A URL
   da imagem tratada como string traduzível (se o idioma vier vazio, src="" = imagem sumida).
Por que quebra no Braze: tag dentro de atributo/keyword corrompe a marcação ou zera o atributo por
locale. (Tags {%translation%} devem envolver SOMENTE texto de corpo, nunca ficar dentro de <...>.)

Observação honesta: parte das tags em alt do p_1785746541286 (id27/30/33) provavelmente foram
introduzidas pelo fix anterior (2026-08-05, quando "re-tagueei a ocorrência visível" de frases que
só existem como alt de imagem). Este fix desfaz isso.

No p_1785404592310 os 16 marcadores em markup estavam todos dentro de comentários
`<!-- ===== SECTION: ... ===== -->` (o mesmo bug de comentário do fix anterior).

===============================================================================
CORREÇÃO (decisão do usuário: "destaguear e remover as linhas")
===============================================================================
Regra aplicada: remover TODO marcador ({%translation idN%} e {%endtranslation%}) cuja posição esteja
dentro de <...> (atributo, keyword OU comentário), preservando o texto literal em volta:
  - `cross{%translation id22%}or{%endtranslation%}igin` -> `crossorigin`
  - `alt="{%translation id27%}Not a gym person?{%endtranslation%}"` -> `alt="Not a gym person?"`
  - `src="{%translation id2%}URL{%endtranslation%}"` -> `src="URL"`
Depois, toda linha de CSV cujo id ficou SEM tag no corpo (órfã) é removida.

Detecção "dentro de <...>": para cada marcador em offset p, lastIndexOf('<',p) > lastIndexOf('>',p).
Funciona por marcador, sem tocar em texto de corpo legítimo nem nos condicionais MSO/VML
(<!--[if mso]>...<![endif]-->), cujo conteúdo real fica APÓS um '>' e portanto é preservado.
