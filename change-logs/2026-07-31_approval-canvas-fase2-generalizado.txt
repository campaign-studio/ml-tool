===============================================================================
POR QUÊ
===============================================================================
A Approval View só sabia mostrar UM item lido do S global, um frame por idioma. A pasta
precisa de uma visão "Approve by Locale": um idioma fixo, um frame por CAMPANHA/ITEM da
pasta, todos naquele mesmo idioma. Em vez de reimplementar (comentários/threads/presença/
PNG/aprovação de novo), a Fase 2 GENERALIZA o canvas por um modelo de descritor de frame,
onde cada frame sabe qual item ele representa e "empresta" o S global só na hora de renderizar.

===============================================================================
DESIGN — "FRAME DESCRIPTOR" + ATIVAÇÃO POR FRAME
===============================================================================
Novos estados no topo do módulo (após approvalLangs):
  _avMode      : 'single' | 'locale'
  _avLocale    : locale fixo quando mode === 'locale'
  _avFrames    : lista de descritores, reconstruída a cada render (avBuildFrames)
  _avFramesByKey: índice key -> descritor

avBuildFrames():
  - single: um frame por idioma (approvalLangs). key === cssSafeLang(lang) — IDÊNTICO aos ids
    de DOM de antes, então o comportamento single não muda.
  - locale: um frame por item da pasta que contenha _avLocale. key === 'it'+índice do item.
  Cada descritor carrega: key, lang, isOrig, itemIndex, item, type, title (+ country no single).

avActivateFrame(f):
  - No modo locale, aponta S (+ _campaignItemIndex + flags _campaignPushPreview/_campaignInappPreview)
    pro item do frame via activateCampaignItemIntoS, pra que TODO o código baseado em S opere no
    item certo. No single é NO-OP (S já está correto).

avCommitIfLocale(): commitCampaignItemApprovalState()+scheduleCampaignAutosave() (só no locale),
  chamado SÍNCRONO após cada escrita em S, antes que a re-renderização ative outro frame e
  sobrescreva o S — assim a escrita nunca se perde.

avFrameOwningComment(id): acha o frame/item dono de um comentário (por id). Usado pela sidebar
  agregada e pelas ações por id (reply/verify/highlight/delete) pra rotear ao item certo. No
  single retorna null (o caller usa o path S normal, inalterado).

O QUE MUDOU (modules/approval-canvas.js)
===============================================================================
Funções que passaram a ser DESCRIPTOR-DRIVEN (recebem o descritor f, ativam o frame no topo,
usam f.key nos ids de DOM e f.lang no conteúdo):
  - renderApprovalGrid: monta frames por avBuildFrames; x ACUMULADO (larguras variam por frame
    no locale); título single = bandeira/país/lang/badge-origin; título locale = ícone 📄 + nome
    do item + rótulo de tipo (Email/In-app/Push), SEM país e SEM badge de origem; cond-branch
    escondido no locale; ids avVp-${f.key}/avApproveSlot-${f.key}.
  - avContentWidth / avFitToFrames: somam larguras POR frame (avFrameWFor/avFrameGapFor a partir
    de f.type — sem ativar S no loop de medição, que roda a cada tick de scroll), não mais
    langs.length*(frameW+gap). Mesma lógica de scale/tx/ty.
  - renderFrameApproveSlot(f): id por f.key; done por isLangApproved(S.approvalDoneByLang, f.lang);
    onclick passa f.key.
  - buildPushFrameHtml(f) / buildApprovalFrameHtml(f) / loadApprovalFrame(f): ativam o frame;
    no script injetado do iframe, os postMessages av-height/av-selection/av-wheel agora mandam
    key: f.key (substitui o antigo lang:). initH por f.type.
  - renderApprovalPins(f): ativa o frame; vp por f.key; filtra S.approvalComments por f.lang.
  - onFrameSelection(data): resolve f = _avFramesByKey[data.key]; ativa; guarda de origem via
    f.isOrig (mantida no single); grava key/itemIndex no _pendingPin.
  - openNewPinBox(f, ...): grava _pendingPin.key/_pendingPin.itemIndex.
  - submitNewPin: resolve o frame por _pendingPin.key e ativa ANTES de addApprovalComment;
    avCommitIfLocale() síncrono depois; renderApprovalPins(f).
  - markLangApproved(key) / undoLangApproval(key): o parâmetro agora é a KEY do frame (no single
    key===cssSafeLang(lang), então callers antigos seguem funcionando). avResolveFrameKey resolve
    o descritor (com fallback defensivo por cssSafeLang). Toggla S.approvalDoneByLang[f.lang]
    exatamente como antes; avCommitIfLocale() no locale.
  - setApprovalCondBranch: loop por avBuildFrames -> avActivateFrame + loadApprovalFrame.
  - renderApprovalSidebar: single INALTERADO (lê S.approvalComments). Locale AGREGA os comentários
    de todos os frames (item.approvalComments filtrados a _avLocale), rendeiriza cada card com o
    frame dono ATIVADO antes (pra isLangApproved etc. lerem o item certo).
  - deleteApprovalComment/toggleApprovalReplyBox/postApprovalReply/toggleApprovalVerify/
    highlightApprovalComment: no locale, avFrameOwningComment(id) -> avActivateFrame antes de
    rodar a lógica S existente; avCommitIfLocale após mutação; highlight usa o vp do frame dono.
  - renderApprovalDoneBanner: single conta idiomas aprovados; locale conta ITENS (assets)
    aprovados pro _avLocale, agregando sobre os frames.
  - saveAvEditModal: recarrega o preview via descritor resolvido (loadApprovalFrame(editFrame)).

Entradas/saídas:
  - openApprovalView(): seta _avMode='single'; _avLocale=null no topo (antes do guard de S.rawHtml).
    Resto inalterado.
  - NOVO openApprovalViewByLocale(locale): seta modo locale, subtítulo = nome da pasta + locale,
